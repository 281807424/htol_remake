# 客户端效果字典

本文整理原客户端对单位效果的静态映射、绘制规则和可由资源索引确认的动画时序。它是客户端呈现字典，不是技能数据库：技能 ID、效果的施放者/目标、范围、实际持续时间等服务器运行时数据并未从本客户端静态表中恢复。

## 证据来源与置信度

- `original_cfr/bh.java` 的静态数组 `ae` 将效果 ID 1–51 映射为精灵 ID、动画组、标志和绘制层级；`p(int)` 按此表创建效果动画。
- `original_cfr/cc.java` 的 1242 消息解析器读取单位 ID、效果 ID 和可选坐标，并把效果添加到该单位。
- `sprite_library.json` 提供动画组帧数和各帧时长。下表的总时长是帧时长之和，不等同于状态/效果在游戏中的实际持续时间。
- 中文名称只在 `remake_demo/scripts/prepare-assets.mjs` 已有的人工命名覆盖表明确给出时列出。它们是本项目的资源识别名，不是原客户端内置的技能名；其他项只用资源编号，不根据图像外观推断语义。

置信度约定：

- **高（代码）**：效果 ID、精灵/动画组、标志、绘制层级、协议字段和绘制路径由客户端源码直接确定。
- **高（资源索引）**：帧数及资源动画时长来自导出的动画索引。
- **中（人工资源名）**：下表标记为“人工名”的名称来自项目资源覆盖表，便于查找，不代表服务端技能关联已被证实。

## 标志与绘制规则

标志是客户端静态表中的位值，可组合使用：

| 位 | 客户端行为 |
|:---:|---|
| `0x01` | 动画循环播放。动画结束时客户端不会因为播放完毕而移除此效果。 |
| `0x02` | 动画结束后保留末帧，等待移除消息；不会由客户端按普通结束逻辑自动移除。 |
| `0x04` | 参与客户端的特殊效果绘制启用判断；不是挂点或“附着到身体”的标记。 |
| `0x08` | 常规单位绘制路径将效果绘制坐标重置为 `(0, 0)`。若 1242 消息另带坐标，解析器会保存该坐标并在绘制时优先使用。 |
| `0x10` | 对角色单位尝试使用当前动作/武器 AO 坐标作为效果绘制位置；仅适用于满足角色动作状态条件的情况。 |

单位效果由 `bh` 按层级分成实体前、实体后两组绘制。无显式坐标时，常规位置基于单位在地图上的位置；带坐标时，绘制位置改用消息内的效果专属坐标。`0x10` 的角色动作挂点逻辑会覆盖前述坐标计算，并且还要求角色处于可用的动作状态。

动画自身的帧时长不应与状态时长混为一谈：非循环动画播放完后，客户端通常自动移除；`0x01` 会循环；`0x02` 会保留结束帧直至服务端移除。实际效果何时添加、持续多久以及何时移除，均可能由服务端消息控制。

## 协议能确定什么

客户端 1242 消息的解析顺序为：

1. 读取单位 ID 和效果数量。
2. 对每项读取效果 ID，并调用该单位的效果添加逻辑。
3. 读取坐标标记；若标记为 1，再读取两个 `short` 作为该效果的位置。

因此可以确认“某个效果被加到消息指定的单位”，带坐标时也可确认客户端使用了该效果专属坐标。但没有原服务端消息记录时，无法仅凭客户端确定：

- 哪个技能或攻击触发了某个效果 ID，施法者是谁；
- 目标是自身、友方、敌方还是地面位置；
- 技能射程、作用半径、命中规则或影响目标数量；
- 服务器给出的持续时间、叠加规则、驱散规则及伤害/控制数值。

攻击动作消息和效果添加消息是不同的客户端处理路径；视觉相似、命名相似或效果素材出现在某个技能演示中，都不足以证明该技能在原服一定施加该效果。
