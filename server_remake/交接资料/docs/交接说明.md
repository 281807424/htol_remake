构建命令（Windows / PowerShell）：

```powershell

powershell -NoProfile -ExecutionPolicy Bypass -File work\build_server.ps1

# 全量：smali 回编 + 重打包 + zipalign + 签名
powershell -NoProfile -ExecutionPolicy Bypass -File work\build.ps1
```

工具链（都在 `work\tools`）：baksmali/smali 2.5.2、build-tools r34（aapt2/zipalign/apksigner）、d8、JDK 17。

模拟器联调：MuMu 12，`adb` 需 `$env:ANDROID_ADB_SERVER_PORT=5039`；
设备名会变（`emulator-5556` / `127.0.0.1:16384`），**connect + install + 启动 + 截图必须放在同一条命令里**，否则 daemon 重启后设备会消失。

## 4. 主界面血条（字段级）

`CGame.updateGameUi()`（`work/decomp/CGame.java` 约 13820 行）：

```java
if (m_Properties[4] != 0 && m_Properties[5] != 0 && s_MaxExp != 0) {
    s_playerHPWidth  = s_CurHp * 116 / m_Properties[4];
    s_playerMPWidth  = s_CurMp * 114 / m_Properties[5];
    s_playerExpWidth = s_Exp * 780 / s_MaxExp;
}
```

绘制在 `CGame.PaintHeadState()`：红条 `fillRect(110,70,HPWidth,6)`、蓝条 `(108,80)`、经验条 `(7,472)`（800×480 虚拟分辨率）。

| 字段 | 含义 | 谁设置 |
|---|---|---|
| `CPlayer.s_CurHp` / `s_CurMp` | 当前血/蓝 | 2111 mask&1 / mask&4 |
| `m_Properties[4]` / `[5]` | 最大血/蓝 | 2111 mask&2 / mask&8，或 623 |
| `s_MaxExp` | 升级所需经验 | 622 倒数第 4 个 int |
| `s_playerHPWidth` 等 | 条宽像素 | updateGameUi 每帧算 |

**血条不显示的常见原因**：622 少写字段导致解析提前中断 → `s_MaxExp=0` → 上面的 `if` 整块跳过。

## 6. 已知问题 / 坑（接手重点）

1. **装备等级用错参数（确实存在的 bug）**
   `dropEquipment()` 把 `monsterLevel` 直接当档位索引传给 `makeEquip(c, idx, …)`，
   而 `makeEquip` 里 `lvl = 10 + idx*5`，idx 被 clamp 到 0..12。
   结果：**打 10 级以上怪几乎必掉 70 级装备**。
   正确写法：`idx = clamp((monsterLevel - 10) / 5, 0, 12)` 或 `idx = clamp(monsterLevel/5 - 2, 0, 12)`。

2. **2108 对自己不播动画**
   `OnRecv_Attack()` 里 `if ((!a.IsPlayer()) || (a.m_IsHost)) { if (a.IsMonster()) … }`
   —— 本地玩家（host）既不进 monster 分支也不进 else 分支，**服务端发的攻击动画对本地角色无效**。
   自己的动作只能由客户端本地 `sendActorAttack()` 触发（即客户端真的发 601）。
   若服务端“代打”太快、怪一死目标就丢，客户端就永远不发 601 → 自己一直站着不动。

3. **攻击动画 id 的权威表**（反编译 `Config` 接口）
   ```java
   CHAR_PHYATT_ANIMS = {6,8, 6,8, 6,8};   // [job*2]=起, [job*2+1]=止
   GetWeaponAnimID(): 空手→43；剑(类型1)→+0；非剑武器(类型2)→+22
   ```
   → 普攻动画：**剑 6/7/8，弓·杖 28/29/30，空手 43**（区间内自增轮播）。
   当前服务端发的是 1/6/9，**不在表内**，属于历史遗留错误值。

4. **521 只有“客户端请求地图”时才被采纳**
   服务端单方面在进图时推 521 → 客户端卡“读取中”；游戏中推 → 被忽略。
   可靠路径：客户端发 3006（菜单→导航）后回 521。

5. **2503 列表对话框直接推会弹“请稍候”**，字段未对齐，不要再用。

6. **1061/背包膨胀**：背包上限 30 格，`addItem` / `loadAll` / `buildInitPack` 三处都要截断，
   否则长时间挂机会攒出 34KB 的 950 包导致客户端反复重连。

7. **仓库**：客户端二进制里没有仓库 UI（967~972 无任何 case），别再找了。

8. **强化界面**：客户端存在强化面板（手动强化/自动强化/帮助），但服务端没有对应协议实装，
   触发路径尚未确认，属于待攻克项。
