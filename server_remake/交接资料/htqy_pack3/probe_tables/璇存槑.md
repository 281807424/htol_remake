## 关键口径（核对前先读）

### 1. 图片序号 = 图标帧号（viewId）

交叉验证结果：**图片序号与项目实测帧号高度吻合**——

- 序号 8~22 分别对应先锋/百步/天灵的腿8/13/18、鞋9/14/19、头10/15/20、衣11/16/21、手12/17/22，与 `交接资料/tables/部位与图标.csv` 逐条一致。
- 序号 29「项链（三职业图标通用）」、37「戒指（三职业图标通用）」也与该文件一致。

所以这张表是**spr23 图标帧的逐帧命名表**，序号就是 viewId。

### 2. 存在三套互相冲突的帧表 —— 这就是要核对的地方

| 来源 | 说法 |
|---|---|
| 用户图片 | 8先锋腿 / 9先锋鞋 / 10先锋头 / 11先锋衣 / 12先锋手 |
| `部位与图标.csv`（本服现行） | 衣=11/16/21、护手=12/17/22、护腿=8/13/18、头盔=10/15/20 —— **与图片吻合** |
| `README.md` L369 旧表 | 10圆环/戒指、11头盔、12手套、20项链、21靴 —— **与图片冲突**（旧口径） |
| `icon_frames.md` 实测 | 帧10圆环、帧11石料、帧12护手、帧14靴、帧15项链、帧16头盔 —— **部分冲突** |

结论：以**图片 + `部位与图标.csv`** 为现行口径；README L369 是早期数据，不要混用；`icon_frames.md` 的 0~29 是另一套资源包（assets/5）的实测，与 spr23 不是同一张表。

### 3. 武器段（序号 2~7）是图片独有的细分

图片把武器拆成 6 类：先锋剑/先锋斧/百步弓/天灵法杖/天灵杖/百步弩，而 `部位与图标.csv` 只给三帧（先锋3/百步4/天灵5）。表中标为「独立命名」，需实机确认每帧真实外观后再决定服务端怎么用。

### 4. 52~172 未实测

图片只拍到序号 51，项目里只实测了 0~59 帧。这 121 项**没有可信数据源**，表中一律标「未实测」，没有编造名称。要补全只有两条路：
- 用户补拍图片剩余部分（推荐，与现有表一致）；
- 实机探针：背包放 F0~F312，每格 viewId=帧号，逐帧截图命名。
