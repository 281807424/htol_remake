# 装备实装 + 品质分级 + NPC 功能（第 3 轮）

## 1. 装备数据（按《角色等级.docx》）

- 生成器：`work/gen_gear.py` 读取 `work/leveldoc2.txt`（由 docx 导出），生成
  `work/java/htol/gamesuper/GearData.java`。
- 覆盖：3 职业 × 13 档（10/15/…/70 级）× 10 部位 = **390 件基础装备**，
  每件 4~5 条属性，数值与文档逐项一致。
- 职业：先锋(0) / 百步(1) / 天灵(2)；部位顺序按客户端 `m_EquipPos`：
  0 衣、1 护手、2 护腿、3 头盔、4 项链、5 戒指1、6 戒指2、7 靴子、8 武器、9 法器。

### 品质

| 品质 | 索引 | 颜色 | 倍率 | 宝石孔 |
|---|---|---|---|---|
| 白 | 0 | 白 | 1.0 | 0 |
| 蓝 | 1 | 蓝 | 1.25 | 1 |
| 紫 | 2 | 紫 | 1.55 | 2 |
| 橙 | 3 | 橙 | 1.9 | 3 |
| 青 | 4 | 青 | 2.3 | 4 |
| 神器 | 5 | 青 | 3.2 | 5 |

- 装备属性 = 文档基础值 × 品质倍率（四舍五入，最低 1）。
- 客户端按 `m_Quality` 取 `CItem.NAME_COLOR[]` 上色，名称后缀“·蓝/·紫/…”。
- 掉落品质权重随地图等级提升：白 62% → 蓝 34% → 紫 18% → 橙 … → 神器 0.6%+。

### 属性下标（客户端 `StringRes.UNIT_ATTR_STR`，从 `assets/1` 字符串包解析）

`0 物攻 1 法攻 2 物防 3 法防 4 暴击 5 命中 6 闪避 7 格挡 8 生命 9 法力
10 速度 11 暴击倍数 12 命中系数 13 坚韧 14 穿透`

百分比属性按 ×100 存整数（文档 0.3% → 30）。

### 装备包格式（已按 `CItem.InitOneItem` 重写 `writeItem`）

`pos, defId, flags(type|quality<<18), subType, name32, viewId, reqLevel, pal,
bindType, buyPrice, sellPrice, goldType, cd, extraDesc16, expandCount,
packed(job|equipPos<<14), suitId, totalDue, curDue, [宝石槽], 4 组属性
(byte count + [byte idx, ushort val]), wuXing, originPrice, identifyFactor,
identifyGoldType, equipScore`

旧代码只写 1 组属性且缺字段，客户端会在解析时越界/丢属性。

## 2. 属性实际生效

`CharInfo` 新增 `maxMp/mp/mag/mdef/crit/dodge/hit/block/tough/pen`；
`refreshStats()` 汇总已装备的 15 项属性：

- 生命上限 += Σ生命，法力上限 += Σ法力
- 物攻/法攻/物防/法防 += 对应属性
- 暴击/闪避/命中/格挡/坚韧/穿透 += 对应属性
- 伤害计算：玩家 `atk + random(atk/2)`，按暴击率 ×1.5，减怪物防御；
  怪物伤害减玩家防御，格挡率触发时 ÷3。
- 装备/卸下、升级、掉落、登录载入后都会重新计算。

**实测**：70 级先锋基础生命 2980，装备后人物属性页显示 **3230/3230**、
法力 140（基础 100），证明装备属性已进入面板与实际数值。

## 3. NPC 功能

### 对话（已通）

选中 NPC → `2115 SELECT_TARGET` → `607 CHAT_TO_NPC` → 服务端回
`2200 SCRIPT_DIALOG style=3` 叠加对白框。6 个 NPC 各有台词。

### 药品商人（商店，已能打开并加载货架）

- `607(9101)` → `951` 初始包头（标题/金币类型/1 个“药品”页签）。
- 客户端点页签箭头 → `952`（`byte flag, int shopId, byte flags, int tabId`）
  → 服务端 `951` 页签内容：4 件商品（金创药 10 / 回灵药 15 / 解毒草 20 / 回城符 50），
  每件走完整 `CItem` 格式 + 买价 + 堆叠 + 描述。
- `880` 购买：解析 `index@5 (u16)`、`count@8`，扣金币、入包、刷新 621/950。
- `883` 出售：按背包下标移除、加金币、刷新。
- `1079` 物品操作菜单：回 `1079{0}` 让客户端使用本地购买菜单。

### 传送阵守卫（菜单已下发）

- `607(9104)` → `3007` 社交菜单，13 张地图（自定义 id 1000+）。
- 客户端选中 → `3006(1000+i)` → 服务端 `jumpToMap(i)`。

### 仓库（客户端无 UI，暂不可做）

- ICmdDef 里有 967/968/969/970/971/972，但 NetComm.parseData **没有任何 case**，
  客户端也**没有任何发送 970/971/972 的代码** —— 这个客户端二进制根本没有仓库界面。
- 结论：客户端没有仓库面板，因此改为“无 UI 仓库”：
  点仓库管事（607=9103）切换存/取——第一次把材料（type2、defId>=3）存入，
  再点一次全部取出，均回 2200 提示并写盘保存。
- 存档新增 depot 段；旧存档缺该行时按 0 处理。
- 由于仓库 NPC 点击目标不稳定，入口改为传送阵菜单里的 **“存取材料”**（3007 -> 3003 id 2201）。
- 实测：开门菜单选“存取材料” -> 日志 depot toggle n=2 left=2（存入金创药/回灵药各 1 组），
  弹窗「已存入 2 件材料。再点一次取出。」；再点一次为取出逻辑。
- 取出实测：depot toggle n=2 left=0，材料全部回到背包，仓库清空。

### 修理（已实测）

- 客户端 sendRepairItem 发 **962**；服务端也支持 NPC 直接修理（607→9102）。
- 实测：点铁匠“交互”后弹出「铁匠 / 装备已全部修理。」对话框，
  同时下发 950 装备栏、985 成功包，日志 
epair all。
- 装备耐久目前恒为 1000/1000（没有损耗系统），所以修理表现为“已修复”。

- 实测背包/装备面板正常，无解析错位；镶嵌逻辑尚未做。


### 3007 自定义菜单（新增）

- 服务端 3007 下发自定义菜单（id>=428 + string8 标签）。
- 客户端选中后发的是 **3003**（int 0, int callback, int menuId, ...），不是 3006；
  已在服务端同时路由 3003/3006。
- 药商菜单：购买药品 / 一键出售白装 / 一键出售蓝绿装。
- 收购商（新 NPC 9106）：点交互直接一键出售白装，并回 2200 结果提示。
- 出售已实测：选中收购商（607=9106）后点交互，服务端出售全部白装并回 2200 结果：
  **「已出售 28 件，获得 700 金币。」**，621 金币 17249 -> 17949。
- 之前“点收购商变铁匠”是修理对话框未关闭吞掉了点击，导致 交互 复用了旧目标，并非 id 错位。

  因此批量出售入口暂不可靠；商店买卖改为按 1079 的 defId 直通。
- 1079 现在无论买/卖是否命中都会回一次 951，避免客户端卡“请稍候”。


### 装备名称（按 装备名称.docx 实装）

- 新增 `work/gen_names.py`：解析 `装备名称.docx`，生成
  `work/java/htol/gamesuper/GearNames.java`
  （3 职业 × 13 档 10~70 级 × 10 部位，另含 3 套神器套装名）。
- `makeEquip` 改为按 职业+等级档+部位 取文档名：
  - 白装：直接用文档名，如 先锋 10 级戒指 2 = `铁卫戒指`
  - 蓝/紫/橙/青：文档名 + `·蓝/·紫/·橙/·青`，颜色仍由品质位控制
  - 神器（品质 5）：直接用神器套装名，如 `神器・焚天战斧`
- 老存档里的装备在打包 950 时会调用 `refreshItemName` 自动改名，不需要删号。
- 实测：客户端 950 装备包里解析出文档名 `铁卫戒指`（先锋 10 级戒指 2）。


### 装备部位映射修正（戒指跑到武器上）

两个 bug 叠加：

1. **名称表顺序错位**：文档里的顺序是「武器、头盔、胸甲、护手、护腿、战靴、项链、戒指1、戒指2、法器」，
   服务端内部槽位是「胸甲、护手、护腿、头盔、项链、戒指1、戒指2、靴、武器、法器」。
   `gen_names.py` 现在按 `[2,3,4,1,6,7,8,5,0,9]` 重排后再写入，槽位 8 才是武器名。
2. **equipPos 位域写错**：客户端按顺序读 bit 字段
   （job 2bit、孔 3bit、equipPos 5bit、强化 5bit、jp 4bit），
   原来把 equipPos 写在 `<<14`，客户端读出来全是 0，戒指就被塞进武器槽。
   现在写成 `(uiPos & 31) << 5`，并且：
   - `m_Pos`（950 装备栏 key）= `SLOT_KEY`：胸0 手1 腿2 头3 靴4 戒5 戒6 项链7 武器8 法器9
   - `m_EquipPos`（UI 槽位）= `SLOT_UI`：胸0 手1 腿2 头3 靴4 戒5 项链6 武器7 法器8

实测 950 装备包：`pos=8 铁斧 ui=7`，武器在武器槽、名称正确。
